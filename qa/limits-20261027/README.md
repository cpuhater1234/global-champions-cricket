## What changed

A local IndexedDB checkpoint is committed transactionally with coordinated primary save acceptance. Success waits for transaction completion. Strict durability is requested and reported only when the browser confirms the mode. Updated tabs serialize through the same readwrite store even without Web Locks. Existing Web Locks remain for compatibility with v81. When neither mechanism can safely coordinate a write, automatic saving is refused and the live career remains exportable.

Startup validates current and previous recovery copies. Missing, corrupt or differing browser data presents a dated review of the available careers; it never silently chooses between different valid careers. Reset uses a committed tombstone and generation checks, preventing queued old work from resurrecting cleared careers or replacing a restored career. Queued waits expire after4seconds; an already unabortable commit remains visibly pending until a real terminal event. Final recovery feedback distinguishes saved progress from session-only progress.

## Limits that remain

Firefox content processes are blocked by this environment's native sandbox; no Firefox game assertions completed and no sandbox was disabled. WebKit is headless Linux WPE, not physical Apple/iOS Safari. No human spoken screen-reader, physical-device, installed Safari or operating-system power-loss certification. Browser storage can still be removed by clearing site data or device failure. Downloaded backups remain the independent recovery route. Close older game versions, especially ones that do not cooperate with either save coordinator.

The original historical intermittent-loss cause remains unproven. The former reproducible accepted-localStorage crash rollback is now recoverable in the10 measured final-build crash cycles; this does not prove universal durability.
