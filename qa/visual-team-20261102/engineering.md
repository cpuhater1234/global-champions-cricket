# Build 33 frontend engineering audit

Read-only source review, 2 November 2026. No production changes or browser use. Captures were not present at review time, so these are verified cascade/structure findings, not claims about observed pixels.

## Eight high-leverage causes

1. **Multiple authoritative systems survive into the delivered file.** `deliver/GCC_v8_Playtest_33.html` contains ten style blocks; the original block is ~568 KB and the final decision block ~88 KB. `qa/perfection-20261030/patch.py:176–177` appends charcoal and decision CSS after all legacy CSS. `v8/ui/decision-ui.css` contains 903 `!important` declarations. Consequently a later rule is not necessarily authoritative: selector specificity and importance still determine which property wins. Safe fix: keep the pinned baseline, but consolidate the *existing final two source files* into deliberate token/base/component/view/responsive sections, one canonical declaration per component property. Preserve necessary legacy bridges explicitly; do not simply remove importance or introduce `@layer` (unlayered legacy rules would win).

2. **Tokens do not span the actual rendering roots.** `arcade-charcoal.css:2,96` defines global GCC tokens twice, while `decision-ui.css:2` creates a second, cooler `--ui-*` palette only below `.gccui`. Player and trade dialogs are siblings outside that wrapper and hard-code similar but different colors (`decision-ui.css:592–653,718–727`). Safe fix: map one set of semantic surface/text/rule/spacing tokens at both `#g8app` and `#g8dialog`; keep `--club-accent`, `--club-ink`, `--side`, and `--rating-color` as separate authored identity/data channels. Replace repeated color literals in existing final rules, without touching engine theme data.

3. **Heading treatment resets only selected properties on selected pages.** `decision-ui.css:4–7` normalizes h1–h3 only inside `.gccui`; dialog and legacy campaign headings have independent repairs at `:305–323,334–350,395–405,637–646,704`. The baseline has global h1/h2 display font and uppercase rules, plus later alternate root/display rules. This is a direct reason new or uncovered pages can inherit old typography. Safe fix: establish shared heading/body/eyebrow/numeric text roles for app and dialog, then explicit club badge/logo exceptions. Normalize family, size, weight, line-height, case, letter spacing, margins, and wrapping together. Do not change approved mark or crest glyph typography.

4. **Decision rows are page forks of one component.** Shared legacy rules live at `arcade-charcoal.css:35,179–181`; match decisions are restyled at `decision-ui.css:197–203,379–383,416–417,559–564,583–590`; offseason adds a grid variant at `:732–741`. These rules independently change layout, typography, spacing, and action sizing. This makes reason copy and actions dependent on the parent route. Safe fix: define one canonical decision row with a shrinkable text column, explicit title/reason/detail roles, and one action column; define only a compact variant where necessary. Use the same markup class from the shared story/decision renderer, keeping data-action and arguments unchanged. Stack actions when text cannot retain useful width.

5. **Panel primitives are not the common surface abstraction.** New `.gccuiPanel`/head (`decision-ui.css:18–21`) coexist with long legacy surface selector lists (`arcade-charcoal.css:10–16,54–60`) and individual dossier/analysis panels (`decision-ui.css:611–628,638–653`). Border weight, inner padding, headers, and shadows are independently authored. Safe fix: reuse shared panel/head/body tokens on these existing selectors first. Only add a shared class when the source renderer is already being touched. One outer frame and quiet inner rules can be enforced without rewriting every view.

6. **Late responsive patches are interleaved with desktop declarations.** Player summary layout is first flex (`decision-ui.css:190–195`), adjusted again at `:305–323`, and ultimately grid (`:631–649`). Team-analysis header wrap is changed at `:334–350`, reversed at `:377–378`, then changed back below 600px (`:389`). Home stadium fit changes from contain (`:300`) to cover (`:376`). These are concrete obsolete states retained in the cascade. Safe fix: fold each component into one base block with its responsive variants immediately following. Preserve the final effective behavior before making aesthetic changes; compare computed styles at 360, 390, 768, 1024, and 1440px.

7. **Wrapper-based coverage and string matching make page parity fragile.** `decision-ui.js:41` wraps only the non-draft dynasty branch; `:53` replaces old headings only when `html.startsWith(prefix)` matches exact rendered HTML; result and finals repeat that pattern later in the file. Legacy children therefore retain different treatment whenever a prefix differs. Safe fix: replace exact-string heading substitution with a shared view heading call in the source renderer as a bounded follow-up; retain wrappers and commands. Meanwhile inventory every route and dialog against the same visual components, including draft introductions, annual transitions, spectator finals, and empty states. Do not infer coverage from `.gccui` alone.

8. **Alignment is overdependent on element position rather than content roles.** Table rules center every non-first column (`decision-ui.css:166`) and later special-case ladder club cells (`:655–657`). Archive has its own first-column widths (`:695–707`). Player overview uses `display:contents` on a legacy wrapper and assumes record panels fill both columns (`:609–617`). Safe fix: add semantic name/numeric/status column classes to affected renderers and apply one shared table pattern; preserve header associations. Keep overview placement explicit per panel rather than relying on arbitrary child order. Test long player/club names, empty tables, and one-/three-digit values.

## Safe implementation sequence

1. Freeze Build 33 and record current computed styles/captures for every route and modal before consolidation. Keep saves/manual XI behavior as regression invariants.
2. Consolidate the final CSS sources by component while preserving current effective values. No baseline removal, no engine changes, no new visual assets. Regenerate via the pinned patch workflow.
3. Apply agreed tokens and typography once across both roots; migrate decision rows, panels, buttons, and tables to shared rules. Remove superseded declarations in place rather than appending another tail override.
4. Verify desktop/mobile route matrix, all club colors/inks, rating colors, focus/disabled/selected states, and long-content wrapping. Compare saved-career load, manual XI move/swap, player dialog navigation, trades, match playback, result/scorebook, finals, offseason, and archive.
5. Only after the visual matrix passes, deliver a new numbered build. A reduced CSS file alone is not proof of visual parity.
