# GCC calibration and remaining validation Implementation Plan

> Execute inline with independent identity/accessibility domains and one final fresh review.

**Goal:** Close every technically accessible remaining gate and deliver reviewable material for the human/hardware gates.
**Architecture:** Keep the published single-file baseline immutable. Produce evidence-keyed datasets and a chronological calibration model outside production first; apply only verified improvements to a versioned new-career path. Preserve all stored legacy future abilities.
**Tech Stack:** Python, SQLite/SciPy, Node VM, Playwright, official Cricsheet sources, GitHub.
**Spec:** docs/superpowers/specs/2026-10-24-calibration-completion-design.md

## Constraints
- No guessed identity/duplicate-person assignments, no silently certified estimates.
- No target-year/future outcomes in any forecast or2023–2026 hyperparameter tuning. Walk-forward forecasts may use earlier completed test years; a separate locked2022 model predicts the whole test block. Validation2020–2022; earlier records for fit/priors. Rolling predictions use only records before each target year.
- No changes to accepted trade/departure/snake rules, manual XI or established saved outcomes.
- Real novice/returning/physical/screen-reader participants must be explicitly distinguished from automated evidence.

## Review focus
Wrong initials/duplicate names; future data leakage; missing/shortened innings; sparse secondary skills or disconnected opponents; legacy/private save methods; live-score accessibility and extreme reflow.
